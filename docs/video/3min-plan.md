## 目的

- 見た人が「触ってみたい」「これは新しい」と感じること
- 審査員は、アプリを触る前にまず動画を見て判断すると言われている（公開情報・参加者のブログより）

### 同じ主催者の前回（Built with Opus 4.6、2026年2月）の審査基準（参考）

| 項目 | 配点 | 中身 |
|---|---|---|
| デモ | 30% | 動くか、印象に残るか、見ていて面白いか |
| 影響 | 25% | 現実での可能性、誰の役に立つか、課題に合っているか |
| モデルの使い方 | 25% | 創造的に使っているか、単なる組み込みを超えているか |
| 深さと完成度 | 20% | 最初の案から先へ進めたか、作りがしっかりしているか |

- 動画は最大3分、YouTube や Loom などで公開。1次審査は非同期の審査で上位6組、2次審査では上位6組の3分の動画を流して審査した
- 前回の上位作（医師が作った診療後の支援ツール）は、「現役の医師が自分で作った」ことを影響の強みとし、スライドより物語で見せる方針だった

### 作った人の背景・経緯を入れるべきか

**入れたほうがよい（ほぼ必須と考える）。** 規則として求められているという記述は見つからなかったが、次の理由から：

1. 今回の方向性①が「あなたが一番よく知っていること」から作ること。看護師としての経験そのものが、作品がこの方向性に合っていることの根拠になる
2. 「影響」の審査で、現場の人が自分の課題を解いていることが強みになる（前回の上位作と同じ構図）
3. 「AIは医療判断をしない」「未確認と0を分ける」などの設計が、現場を知る人の判断だと伝わる

ただし長くしない（20〜30秒）。経緯は「訓練で見た一場面」に絞り、残りの時間を実際に動く画面に使う。

## 構成の案（3分＝180秒）

| 時間 | 内容 | ねらい |
|---|---|---|
| 0:00–0:12 | 冒頭：地鳴りと地図から病院へ。大規模災害時の病院の対応と BCP（「冒頭の言い回しの案」の案B） | つかみ |
| 0:12–0:40 | **経緯**：災害対応に深く関わる病院の看護師として、院内BCPの訓練に参加してきた。訓練のたびに残る、コミュニケーションと情報伝達の課題（ホワイトボードと無線、聞き取ったメモ。「誰がどこにいるか」「頼んだことが実行されたか」）。根拠の資料を1〜2つ画面に出す。日々の業務で訓練を重ねにくい | 作った人の背景・テーマ1・影響 |
| 0:40–1:35 | **実運用のデモ（物語仕立て）**：架空の地震発生後の10分を追う。救急外来で患者を登録→本部の画面に即時に出る（2台並べて）、搬送の指示→出発→到着（記録済み／未記録の区別）、院内の状況の「未確認」と「0」の違い、同じタッグ番号の警告（止めずに理由を記録）、掲示用画面、白黒で読める印刷 | デモ・深さ |
| 1:35–2:25 | **AI訓練のデモ**：シナリオを開始すると、救急外来や手術室の「部署役」の AI から無線で報告が届く。参加者は聞いて自分で入力する。終わると振り返りで、真の状態と自分の記録のずれが根拠つきで示される | 「触ってみたい」の中心・モデルの使い方 |
| 2:25–2:45 | **安全のしくみ**：AI は決まった形の「提案」しか出せず、サーバーが検証してから反映する（strict tool use）。AI は医療判断をしない。実運用では AI を使わず、API が止まっても動く | 信頼・医療分野での責任 |
| 2:45–2:55 | **どの病院でも**：病院の作成画面で中規模病院の設定を作り、同じ画面がそのまま動く | 30秒版の「総合病院から中規模病院まで」をここで具体的に見せる |
| 2:55–3:00 | 締め：ツール名、リポジトリ、「データはすべて架空です」 | |

### 「画期的」と伝えるための見せ方の候補

- **訓練で使った画面を、そのまま本番で使う**：訓練と実運用が同じ画面・同じ病院設定。これを一言で言える場面をつくる
- **AI が「他の部署」になる**：一人でも、他部署を相手にした机上訓練ができる。無線で次々と報告が届く場面は動きがあり、見ていて面白い
- **記録が消えない**：訂正しても履歴が残る。振り返りの根拠になる
- **Claude Code での作り方**（短く）：看護師が Claude Code で作ったこと、自作の Skill や点検用のサブエージェント（`ux-reviewer`、`invariant-auditor`）、自動テストの数。審査の「深さ」向け。入れるなら 10秒程度

## 応募テーマとの対応：テーマ1「あなたにしかない深さを。」

テーマ1を選ぶのが自然（設計書 §1・README とも一致）。映像の中で、テーマの言葉と次のように対応させる。

| テーマ1の言葉 | タシカメでの対応 |
|---|---|
| あなたが一番よく知っている世界を出発点に | 災害対応に深く関わる病院の看護師として、院内BCPの訓練に参加してきた |
| その中に身を置いてきた人だからこそ気づける「足りないもの」 | 訓練のたびに残る、院内の情報伝達の課題。「未確認」と「0」が混ざる、頼んだことと実行されたことが分からない |
| 隣にいる仲間、これから引き継いでいく人たち | 同じ病院の職員が使う実務ツール。訓練モードで、本部の調整のやり方を次の人が練習できる |
| 「そういうものだ」と諦めてきた日々の不便 | ホワイトボードと無線と紙の記録。大きな訓練は年に数回しかできない |

テーマ2（災害への備え、人手不足）にも重なるが、両方を言うと焦点がぼける。映像ではテーマ1に絞り、「中規模病院でも使える」はテーマ2寄りの補足として短く触れる程度にする。

使い方の方針：
- 映像では数字を1つか2つに絞る（例：「BCPを作っていた病院は4分の1」）。画面の隅に出典を小さく出す
- 古い数字（2018年）は年を必ず添える。最新の値が見つかればそちらを使う
- 被災した病院の名前は出さない（「被災地の病院では」とする）
- 「未確認」の資料は、制作前に原文を開いて確かめるまで映像に使わない

## 冒頭の言い回しの案

「BCP」は医療者には通じるが、一般の視聴者や海外の審査員には通じにくい。**最初に一度だけ「BCP、事業継続計画」と言い、画面に短い説明を添える**のがよい。

- 案A（BCPを前に出す）：「大規模災害のとき、病院は患者を受け入れながら、診療を続けなければなりません。そのための計画が、BCP、事業継続計画です。」
  - 英語：In a major disaster, hospitals must keep caring for patients as more arrive. The plan for this is called a BCP: a business continuity plan.
- **採用：案B**（2026-11-05 利用者が決定）（課題へすぐつなぐ）：「大規模災害に備え、病院はBCPをつくり、訓練を重ねています。それでも、訓練のたびに残る課題があります。情報の伝達です。」
  - 英語：Hospitals prepare for major disasters with continuity plans and drills. Yet one problem remains after every drill: communication.
- 経緯へのつなぎ：「私は、災害対応に深く関わる病院で、看護師として働いています。」
