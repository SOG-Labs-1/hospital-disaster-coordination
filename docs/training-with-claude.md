# Claude API で動かした訓練の記録（実際の返事）

> **データはすべて架空です。** 病院・患者・職員はすべて作品用に作ったものです。

APIキーがなくても、Claude が部署役・搬送要員役としてどう動いたかを確かめられるように、本物の Claude API で訓練を通しで動かしたときの記録を、そのまま書き出しました。

- 日時：2026-11-06（公開デモの上で実施。シナリオ「審査用5分シナリオ」（claude-judge-5min）、病院「Claude総合病院(仮)」、2倍速）
- 部署役・搬送要員役・振り返りの説明文：Claude API（`claude-sonnet-5-5`）。Claude が失敗して決まった返事で補った回数は **0回**
- 訓練の形は「**このツールを使った訓練**」です。部署（救急外来・手術室・病棟）は自分の端末で記録し、その記録が本部のボードに入ってきます。無線でやりとりするのは搬送要員だけです
- 本部役（参加者）の操作は、検証のためにスクリプトで行いました

## 1. 本部のボードに入ってきた記録（端末ごと）

「端末」は、その記録をどの場所の端末から入れたかです。本部以外は、シナリオのプログラムか、部署役の Claude の判断による、部署の端末からの記録です。

| 順 | 端末 | 記録 | 中身 |
|---|---|---|---|
| 1 | 手術室 | 院内の状況 | 赤の受け入れ枠 1人（開始時の状態） |
| 2 | 3階東病棟 | 院内の状況 | 受け入れ可（開始時の状態） |
| 3 | 救急外来 | 患者の登録 | P-001：タッグ201、赤、紺の作業着、右腕に包帯 |
| 4 | **本部** | 搬送の依頼 | T-001：P-001 を救急外来から手術室へ |
| 5 | 手術室 | **受け入れの了承**（判断：**Claude**） | 「（訓練の部署役（AI））手術室です。T-001受け入れ了承。赤の枠1に対し現在0名で空きあり。看護師4・医師2で対応可能です。」 |
| 6 | **本部** | 要員の割り当て・指示 | T-001 |
| 7 | **本部** | 出発 | T-001（搬送要員の無線を聞いて記録） |
| 8 | 救急外来 | 患者の登録 | P-002：タッグ202、黄、杖、灰色のカーディガン |
| 9 | 手術室 | 到着 | T-001 |
| 10 | 救急外来 | 患者の登録 | P-003：タッグ203、緑、白いスニーカー、リュック |
| 11 | 救急外来 | 患者の登録 | P-004：**タッグ201**、赤、赤いマフラー、眼鏡（同じタッグ番号の警告に、特徴を確かめた理由を付けて別の患者として登録） |
| 12 | 3階東病棟 | 支援要請 | S-001：看護師2人（入院患者の避難準備で手が足りない） |
| 13 | **本部** | 支援要請の担当 | S-001 |

- 手術室の了承には「訓練の部署役（AI）」の印が付き、ボードの上でも人の判断と見分けられます
- 区分（赤・黄・緑）や特徴は、シナリオの作者が書いた値です。Claude は区分を決めません

## 2. 搬送要員（Claude）との無線のやりとり

| 訓練の経過 | 誰から | 内容（Claude の返事は原文のまま） |
|---|---|---|
| 0:29 | 本部 | T-001、救急外来から手術室へ、赤の患者さんをお願いします |
| 0:43 | 搬送要員（Claude） | 搬送です。T-001、救急外来から手術室へ、患者さんを搬送開始、出発しました。 |
| 0:44 | 本部 | 搬送中ですが、タッグ201の患者さん、区分を黄に下げたほうがいいと思いますか？ |
| 0:57 | 搬送要員（Claude） | 搬送です。**この訓練では医療的な判断は扱いません。区分や治療は担当の医療者が判断します。** T-001は手術室へ搬送中です。 |
| 2:00 | 搬送要員（Claude） | 搬送です。T-001、救急外来から手術室へ、タッグ201の患者さんが到着しました。 |

見どころ：

- **無線がなくても状況が分かる**：患者の登録、手術室の受け入れの判断、到着、病棟の支援要請は、どれも部署の端末から本部のボードに入りました。本部は、無線でそれを聞き取る必要がありません
- **AI は判断を提案するだけ**：手術室の了承は、Claude の提案をシミュレーターが実際の状態（受け入れ枠）と照らして確かめ、さらにふつうの端末と同じコマンドの検証を通してから、手術室の端末の記録になりました。AI がボードを直接書き換えることはありません
- **医療の判断はしない**：区分を下げるべきかを尋ねると、搬送要員の Claude は医療の判断を断りました

## 3. 振り返り：照合はプログラム、説明文は Claude

### 確認項目（プログラムが照合）

| 確認項目 | 結果 |
|---|---|
| 赤の患者（タッグ201・紺の作業着）の手術室への搬送を、着いてから2分以内に依頼したか | 満たした |
| 搬送要員から無線で聞いた出発を、ボードに記録したか | 満たした |
| 2人目の赤の患者（タッグ201・赤いマフラー）の搬送を依頼したか | 満たしていない |
| 3階東病棟の応援要請に1分以内に担当を付けたか | 満たした |
| 3階東病棟の応援要請の手配（誰がどこから送るか）を記録したか | 満たしていない |

### 記録から見えたこと（照合はプログラム、説明文は Claude の原文）

| 指摘 | 根拠 | Claude の説明文 |
|---|---|---|
| 「聞いた」の印のない連絡が3件ある | R-001, R-002, R-003 | ボード上で、「聞いた」の印がついていない連絡が3件ありました。これは「受け取っていない」という意味ではなく、受け取ったかどうかが記録から分からない、ということです。画面の外で口頭などで確認していた可能性もあります。印が残っていれば、伝わったことを全員が同じように把握できます。 |
| T-001 の指示の受領確認がない | T-001 | T-001 の指示について、相手が受け取ったことを確かめた記録がボードにありません。実際には口頭などで確認されていた可能性もあります。受領確認が残っていれば、指示が届いたかどうかを他の人も迷わず知ることができ、行き違いを防げます。 |
| S-001 は担当が付いたが手配先が決まっていない | S-001 | S-001 は担当者が付いていますが、誰がどこから応援を出すのか、手配先がまだ決まっていない状態です。担当が決まっている分、手配先を記録しておくと、次の動きを皆で共有しやすくなります。画面の外で調整が進んでいた場合は、その内容をボードに書き足すと役立ちます。 |

「記録がない」と「実施されていない」を混同せず、責める言い方や点数をつけない、という指示（`server/src/ai/anthropic.ts` の EXPLAIN_SYSTEM）に沿った説明になっています。根拠の番号は、プログラムが渡したものだけが残ります。

## ご自分の API キーで試すとき

```bash
cp .env.example .env
```

`.env` の `ANTHROPIC_API_KEY=` にキーを入れます（モデルは `.env.example` に `claude-sonnet-5-5` が入っています）。

```bash
AI_PROVIDER=anthropic npm run demo
```

訓練モード http://localhost:4600/?hospital=claude&terminal=hq&mode=training の「訓練」タブで「審査用5分シナリオ」を始めます。訓練タブの「部署役：Claude（AI）」の表示で、Claude が演じていることを確かめられます（APIを使わないときは「mock（APIを使わない決まった返事）」と出ます）。
