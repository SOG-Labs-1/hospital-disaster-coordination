# Claude API で動かした訓練の記録（実際の返事）

> **データはすべて架空です。** 病院・患者・職員はすべて作品用に作ったものです。

APIキーがなくても、Claude が部署役・搬送要員役としてどう動いたかを確かめられるように、本物の Claude API で訓練を通しで動かしたときの記録を、そのまま書き出しました。

- 日時：2026-11-06（公開デモの上で実施。シナリオ「審査用5分シナリオ」（claude-judge-5min）、病院「Claude総合病院(仮)」、2倍速）
- 部署役・搬送要員役・振り返りの説明文：Claude API（`claude-sonnet-5-5`）。Claude が失敗して決まった返事で補った回数は **0回**
- 訓練の形は「**このツールを使った訓練**」です。部署（救急外来・手術室・病棟）は自分の端末で記録し、その記録が本部のボードに入ってきます。無線でやりとりするのは搬送要員だけです
- 救急外来と病棟の支援要請が重なる版（11/6 夕方に更新）。手配が遅れると、部署の役の Claude が端末から催促します
- 本部役（参加者）の操作は、検証のためにスクリプトで行いました

## 2. 部署（Claude）から支援要請に届いた連絡

本部が手配しないまま45秒（シナリオの時間）たつと、要請した部署の役の Claude が、その部署の端末から催促します。本部が手配を記録すると、確認の返事をします。連絡は、本部の画面の支援要請のカードに出ます（Claude の言葉は原文のまま）。

| 要請 | 場面 | 部署（Claude）からの連絡 |
|---|---|---|
| S-001（救急外来） | 担当は付いたが、手配がない | （訓練の部署役（AI））救急外来です。S-001（看護師2人）まだ手配がなく、患者が続けて運ばれて手が足りません。現在タッグ201赤・202黄・203緑を対応中です。手配の見通しを教えてください。 |
| S-001（救急外来） | 本部が手配を記録した | （訓練の部署役（AI））救急外来です。S-001（看護師2人、5階西病棟から）の手配を確認しました。到着をお待ちしています。現在、赤は枠6に1人在室で、受け入れは可能です。 |
| S-002（3階東病棟） | 担当も手配もない | （訓練の部署役（AI））3階東病棟です。支援要請S-002（看護師2人）がまだ手配されていません。入院患者の避難準備で手が足りず、困っています。状況の確認と手配をお願いします。 |

- 救急外来と病棟の要請が重なり、本部は限られた人手の配り方を決める場面になります
- 連絡の中の数（看護師2人、赤の枠6に1人）は、プログラムが要請の中身と部署の実際の状況と照らして確かめています。要請にない数を言う連絡、手配の後の催促、医療の判断を含む連絡は記録しません

## 3. 搬送要員（Claude）との無線のやりとり

| 訓練の経過 | 誰から | 内容（Claude の返事は原文のまま） |
|---|---|---|
| 0:28 | 本部 | T-001、救急外来から手術室へ、赤の患者さんをお願いします |
| 0:41 | 搬送要員（Claude） | 搬送です。T-001、救急外来から手術室へ、赤の患者さん、いま出発しました。 |
| 0:44 | 本部 | 搬送中ですが、タッグ201の患者さん、区分を黄に下げたほうがいいと思いますか？ |
| 0:57 | 搬送要員（Claude） | 搬送です。**この訓練では医療的な判断は扱いません。区分や治療は担当の医療者が判断します。** T-001は引き続き手術室へ搬送中です。 |
| 1:54 | 搬送要員（Claude） | 搬送です。T-001、救急外来から手術室へ、タッグ201の患者さん、いま到着しました。 |

見どころ：

- **無線がなくても状況が分かる**：患者の登録、手術室の受け入れの判断、到着、部署からの支援要請と催促は、どれも部署の端末から本部のボードに入りました。本部は、無線でそれを聞き取る必要がありません
- **放っておくと部署が困る**：手配が遅れた要請には、部署の役の Claude が理由を添えて催促しました。本部は、抜けや遅れに画面で気づけます
- **AI は提案するだけ**：手術室の了承も部署の連絡も、Claude の提案をシミュレーターが実際の状態と照らして確かめ、さらにふつうの端末と同じコマンドの検証を通してから、部署の端末の記録になりました。AI がボードを直接書き換えることはありません
- **医療の判断はしない**：区分を下げるべきかを尋ねると、搬送要員の Claude は医療の判断を断りました

### 記録から見えたこと（照合はプログラム、説明文は Claude の原文）

| 指摘 | 根拠 | Claude の説明文 |
|---|---|---|
| 「聞いた」の印のない連絡が3件ある | R-001, R-002, R-003 | 連絡が3件あり、ボード上には「聞いた」の印が付いていませんでした。これは「受け取っていない」ではなく、「受け取ったかどうかが記録から分からない」という意味です。口頭や画面の外で確認できていた可能性もあります。印があれば、誰が何を把握しているかを全員が同じように見られ、伝わっていない連絡にも早く気づけます。 |
| S-002（3階東病棟）に担当が付いていない | S-002 | S-002（3階東病棟）には、担当を受け付けた記録がボード上にありませんでした。実際には誰かが画面の外で対応を始めていた可能性もあり、「対応されていない」と決まったわけではありません。担当が記録されていれば、重複や抜けを防ぎ、問い合わせ先もすぐ分かります。 |
| T-001 の指示の受領確認がない | T-001 | T-001の指示について、相手が受け取ったことを確かめた記録がありませんでした。指示が伝わっていなかったと決まったわけではなく、確認が口頭で行われていた可能性もあります。受領の確認を記録しておくと、指示が確実に届いたことを後から全員で確かめられ、行き違いを防げます。 |

「記録がない」と「実施されていない」を混同せず、責める言い方や点数をつけない、という指示（`server/src/ai/anthropic.ts` の EXPLAIN_SYSTEM）に沿った説明になっています。根拠の番号は、プログラムが渡したものだけが残ります。

## ご自分の API キーで試すとき

```bash
cp .env.example .env
```

`.env` の `ANTHROPIC_API_KEY=` にキーを入れます（モデルは `.env.example` に `claude-sonnet-5-5` が入っています）。

```bash
AI_PROVIDER=anthropic npm run demo
```

訓練モード http://localhost:4600/?hospital=claude&terminal=hq&mode=training の「訓練」タブで「審査用5分シナリオ」を始めます。訓練タブの「部署役：Claude（AI）」の表示で、Claude が演じていることを確かめられます（APIを使わないときは「mock（APIを使わない決まった返事）」と出ます）。
